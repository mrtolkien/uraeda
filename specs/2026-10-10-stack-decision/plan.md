# Plan: Technical stack decision

> [!NOTE]
>
> Approved in advance on 2026-10-10: the human skipped the plan review, and will judge the code.
>
> - Review focus: a `specs/` folder holding files at its root, a feature folder name that only looks
>   like a date, an empty frontmatter, a `status` with surrounding spaces, and a `Host` header
>   without its port.
> - New dependencies: clap, serde, serde-saphyr, thiserror, napi-rs v3 in Rust; Hono, fate, React,
>   Astryx, and Testing Library with happy-dom, for tests, in TypeScript.
> - The riskiest tasks are the binding (task 3) and fate (task 4): the spec's fallback applies in
>   task 4.

**Goal:** Set up the repository for Uraeda's tools: a Rust core and the `ura` CLI, a TypeScript
server calling the core through napi-rs, and a React UI with Astryx and fate, proven by a temporary
status slice, with one command for every check.

**Architecture:** A cargo workspace (`crates/core`, `crates/cli`, `crates/binding`) next to a pnpm
workspace (`packages/binding`, `packages/server`, `packages/web`). The binding's npm package builds
the binding crate with napi-rs and commits its generated loader and declarations. The server serves
fate's native protocol on Hono, with a source reading spec folders through the binding. See the
[spec's design](spec.md#design).

**Spec:** [spec.md](spec.md): the plan argues from the spec, so the implementer reads both.

## Review focus

Inputs the spec does not mention, most likely to bite a user first. Each gets a test in the task
that owns the code.

1. **A `specs/` folder holding files, like `README.md`, next to its feature folders**: files are
   skipped, only folders are listed. Task 1.
2. **A folder named like a date that is not one, `2026-13-99-x`, or `2026-10-10` alone**: the first
   is listed (the name pattern is `YYYY-MM-DD-<slug>`, digits only), the second is not, since it has
   no slug. Task 1.
3. **An empty frontmatter, `---` then `---`**: `invalid: no status field`. Task 1.
4. **A status with spaces or another case, `status: Approved`**:
   `invalid: unknown status "Approved"`; statuses are exact. Task 1.
5. **A `Host` header without its port, `127.0.0.1`**: rejected with 403, `Forbidden host`, since a
   browser always sends the port of a non-default port. Task 4.

## Global constraints

From the decisions and the spec, every task's requirements include these:

- Workflow logic, parsing, validation, and workflow states MUST live in the Rust core,
  [`crates/core`](/crates/core/). ([stack](../decisions/stack.md))
- The CLI MUST be written in Rust, in [`crates/cli`](/crates/cli/), build the binary `ura`, and MUST
  NOT need Node or any other runtime to run. ([stack](../decisions/stack.md))
- TypeScript code MUST reach the core only through the binding,
  [`packages/binding`](/packages/binding/), and MUST NOT reimplement its parsing, validation, or
  states. ([stack](../decisions/stack.md))
- The TypeScript types of core data MUST come from the declarations napi-rs generates for the
  binding. They MUST NOT be redeclared by hand in TypeScript. ([stack](../decisions/stack.md))
- The server MUST listen on 127.0.0.1 only, and MUST reject requests whose `Host` is not `127.0.0.1`
  or `localhost` on its port, or whose `Origin`, when present, is not an allowed origin.
  ([stack](../decisions/stack.md))
- `vp run ready` MUST run every check of the repository. A new language, package, crate, or tool
  MUST add its checks to it. ([toolchain](../decisions/toolchain.md))
- Rust code MUST pass `cargo fmt --check`, `cargo clippy` with warnings as errors, and `cargo test`.
  ([toolchain](../decisions/toolchain.md))
- Files generated by napi-rs MUST be committed, and MUST NOT be edited by hand.
  ([toolchain](../decisions/toolchain.md))
- Every file, function, type, and component of the status slice is named `temporary_*` or
  `Temporary*`, or sits in a module so named, and opens with a `TEMPORARY:` comment naming the
  feature that replaces it: `TEMPORARY: replaced by the CLI feature.` or
  `TEMPORARY: replaced by the web UI feature.` ([spec](spec.md#success-criteria), SC-003)
- Every manifest carries `license = "MIT OR Apache-2.0"` (`"license": "MIT OR Apache-2.0"` in
  `package.json`). ([spec](spec.md#components))
- Exact texts: the edge cases and error handling of the [spec](spec.md#edge-cases), copied as
  written.

## Complexity tracking

| Abstraction or exception                      | Why it is needed                                                             | Simpler alternative rejected because                                     |
| --------------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| The binding crate and package                 | The server reaches the core without a second parser (stack decision)         | Calling `ura --json`: rejected by the human in Q1                        |
| The core's `napi` feature                     | Each core type is declared once, and exported to TypeScript unchanged        | Mirror types in the binding: two declarations to keep in step            |
| The server's temporary fate source            | fate ships sources for Prisma and Drizzle only                               | TanStack Query: the fallback, used only if fate's exports do not suffice |
| The host and origin middleware                | A local server must not be reachable from web pages (stack decision)         | No check: any website could read and, later, change the repository       |
| Shared `fixtures/specs/` and the test helpers | The Rust and TypeScript tests check the same files, each test in a few lines | Fixtures per package: three copies of the same broken files              |
