# Spec comments: suggestion vs change needed

## What

Spec comments: suggestion vs change needed

What I want is clear separation of comments that are just general guidelines and do not stop
approval.

I think the simplest is to just allow comments to be used both for approval and revisions.

So the flow would be:

- Spec
- Comments anywhere
- Revision or approval, both accepted with comments

We need for the user to understand that they should ask for a revision if their comments require
functional changes, but don't be too ham-fisted about it.

## Why

Currently it's a bit unclear and the behaviour is not intuitive.
