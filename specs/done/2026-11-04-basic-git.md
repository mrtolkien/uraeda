# Record: Basic git UI in the web UI

> [!NOTE]
>
> The record of a merged feature, not instructions to follow. Started on 2026-11-04, finished on
> 2026-11-05, in [its pull request](https://github.com/mrtolkien/uraeda/pull/97). Its full files are
> in git: `git log -- specs/2026-11-04-basic-git/`.

## What and why

A Git page in the web UI, so the human works fully remotely: they pull `main` after a pull request
merges, push Uraeda's chores, read diffs and the history, stage and commit any file, merge a branch,
fix conflicts, and clean worktrees, without a terminal. It is a simple, generic client in lazygit's
spirit, for the main checkout, and it replaces the Commit page. The human runs these commands, never
an agent.

## Behaviour

- **The page's place**: "Git" is always in the sidebar, "Git · 3 · ↓3" with the changes to commit
  and the commits to pull; the phone's tab shows only while something waits. `Space g`, `g c`, and
  the old `/commit` open `/git`.
- **Sync**: the title reads "main · 3 to pull · 6 to push · fetched just now", "main · no remote",
  "detached at 4f8c2b7", or "main · pull stopped". The server fetches on the page's open and every 5
  minutes, outside the toast, and shows a failed fetch's message on the page. Pull follows
  `pull.rebase`, `pull.ff`, and `branch.<b>.rebase`, and rebases when none is set; autostash follows
  `rebase.autoStash`. Push never forces: when `origin` has commits the branch lacks, "origin has
  commits main lacks: pull first." A credential failure adds "The server runs git without a
  terminal: give it a credential helper or an ssh-agent." A fetch stops after 2 minutes without an
  answer, a pull or a push after 10.
- **Changes**: every changed file of the main checkout is in one tree, with a group of its own for
  each feature's worktree with changes. Each row is a checkbox: Space stages a file or a folder, a
  folder's box is ticked, empty, or mixed, `a` stages or unstages all, Enter folds a folder, and a
  staged file keeps its row. `c` or Ctrl+Enter commits what is staged with the typed message,
  through the human's hooks; the message is unsaved text until its commit lands, and a hook's
  refusal shows above Changes with the files left staged. `d` asks "Discard the changes to <path>?"
  and restores that one file as `HEAD` has it, or deletes a new one; a folder or a conflicted file
  is refused.
- **Diffs and history**: a picked file's or commit's unified diff shows beside the sections on wide
  screens and as its own page on the phone, with "Binary file, 12 KB to 14 KB", and "+2,900 −100"
  with "Show the whole diff" past 1,000 lines or 1 MiB. The history lists the branch's commits
  newest first, ↓ to pull and ↑ to push, 50 at a time; a commit lists its files.
- **Conflicts**: a stopped pull or merge reads "The pull stopped: 1 file conflicts." with Continue
  and Abort, `m` for both. Each file offers its whole sides by branch name ("Use origin/main", "Use
  main"; "Keep the file" and "Delete the file" for a delete); a text file opens in the shared editor
  with a bar over each conflict, "Use origin/main", "Use main", "Use both", saved by the human.
  Continue refuses while a file holds markers, and skips a replayed commit its resolution left
  empty. Abort asks first, "Abort the pull? The resolved files go back as they were." once a file is
  resolved. A stash that could not be put back is a stop of its own, without Abort, its stash kept.
  While a pull or a merge is stopped, every action that commits on `main` is refused, "A pull is
  stopped: continue or abort it first.", before it writes anything.
- **Merge**: "Merge into main…" merges a local or `origin` branch the page lists.
- **Worktrees**: each linked worktree reads merged, has changes, missing, locked, or no changes.
  Clean does what `ura clean` does on a merged feature; Remove takes any other without changes,
  keeping its branch, and a missing one's record alone. Both ask first.
- **Agents**: while a chat's agent works in the main checkout, "An agent works in this checkout."
  and every write of the page is refused, checked as it is queued and again as it lands; a feature's
  group or worktree is refused while that feature's agent works.
- **Uraeda's own commits** commit only their own files, and leave the files the human staged staged.

## Design

The core's `git/` module owns every git rule, reading through gix and writing through `git` from one
runner that never prompts nor opens an editor; the API gathers the page's views and maps a group, a
worktree, or a conflict to what the repository lists, so the web never names a path to act on. The
server serves the views, lands every write in the repository's write queue in the order the calls
came, owns the checkout guard, and runs the fetcher. The web owns presentation only.

- The runner and deadlines: [`git/process.rs`](/crates/core/src/git/process.rs) `git_write`,
  `git_write_within`, which kills a process group.
- The stopped operation and its sides by branch: [`git/stopped.rs`](/crates/core/src/git/stopped.rs)
  `Git::stopped`, `ensure_not_stopped`, the one owner of the stop's refusal, used by commits, pull,
  push, merge, and `place::reach`.
- Reads: [`git/checkout.rs`](/crates/core/src/git/checkout.rs) (files, stages, conflicts, ahead and
  behind), [`git/diff.rs`](/crates/core/src/git/diff.rs) (unified diffs through `gix-diff`, the
  caps), [`git/history.rs`](/crates/core/src/git/history.rs) `history_page`.
- Writes: [`git/remote.rs`](/crates/core/src/git/remote.rs) (fetch, pull and its default, push),
  [`git/staging.rs`](/crates/core/src/git/staging.rs) (stage, unstage, discard, `checked` paths),
  [`git/resolve.rs`](/crates/core/src/git/resolve.rs) (sides, continue, abort, merge),
  [`git/commit.rs`](/crates/core/src/git/commit.rs) `commit_index`.
- The API: [`api/git_page.rs`](/crates/core/src/api/git_page.rs) (the views, `group_root`) and
  [`api/git_writes.rs`](/crates/core/src/api/git_writes.rs); the binding's
  [`git_reads.rs`](/crates/binding/src/git_reads.rs) and
  [`git_writes.rs`](/crates/binding/src/git_writes.rs); the watcher's `Changes::git` in
  [`watch.rs`](/crates/core/src/watch.rs).
- The server: [`fate/views-git.ts`](/packages/server/src/fate/views-git.ts),
  [`fate/git-mutations.ts`](/packages/server/src/fate/git-mutations.ts),
  [`fate/git-guard.ts`](/packages/server/src/fate/git-guard.ts),
  [`git-fetch.ts`](/packages/server/src/git-fetch.ts), and `WriteQueue`'s `background` and `arrive`
  in [`writes/queue.ts`](/packages/server/src/writes/queue.ts).
- The web: [`git/`](/packages/web/src/git/) (`GitPage.tsx`, the tree in `tree.ts`, `Sync.tsx`,
  `ChangesTree.tsx`, `Diff.tsx`, `History.tsx`, `Worktrees.tsx`, `Conflicts.tsx`,
  `ConflictEditor.tsx`), the conflict bar in
  [`fields/editor/conflictBar.ts`](/packages/web/src/fields/editor/conflictBar.ts) over
  [`conflicts.ts`](/packages/web/src/fields/editor/conflicts.ts), and the editor's shared save in
  [`fields/useFileEditor.ts`](/packages/web/src/fields/useFileEditor.ts).

## Gotchas

- Sides are named from git's stages by branch, because during a rebase git's "ours" is the branch
  rebased onto: [`git/stopped.rs`](/crates/core/src/git/stopped.rs).
- A fetch's deadline kills the whole process group, since killing `git` alone leaves ssh or
  upload-pack holding the output pipe: [`git/process.rs`](/crates/core/src/git/process.rs), with
  `libc` on unix.
- A rename conflict lists under its new path only: gix is built without rename detection, and git's
  index puts every stage there: [`git/checkout.rs`](/crates/core/src/git/checkout.rs).
- Continue runs `rebase --skip` for an emptied commit: git 2.56's default backend drops it alone,
  the `apply` backend stops on it: [`git/resolve.rs`](/crates/core/src/git/resolve.rs).
- The page's optional fields are sent as `null`, never left out: fate merges a record's fields
  shallowly, so a missing `stopped` would keep its old value:
  [`fate/views-git.ts`](/packages/server/src/fate/views-git.ts).
- `git diff --cached` lists an unmerged path during a stop, before and after nothing changed: tests
  wait on `git ls-files --unmerged` instead.
- The conflict bar's buttons are the browser's, styled from Astryx's tokens: CodeMirror's widgets
  cannot draw Astryx's `Button`: [`conflictBar.ts`](/packages/web/src/fields/editor/conflictBar.ts).
- SC-001's 100 ms holds on a release build (39 ms on Uraeda's repository with 4 worktrees, reading
  the checkouts in parallel); the debug build's benchmark only prints its mean.

#### Q1: Which checkout does the page act on?

**Answer:** C: the main checkout only.

**Answer:** A: the page reads it, but its writes are refused, saying an agent works there.

## Changes after approval

- The start's refusal during a stopped merge reads "A merge is stopped: continue or abort it
  first.", shared with every commit, in place of its own message.
- Uraeda's own commits (proposal and note files, answers, verdicts, the inbox and priorities) commit
  only their files and leave the human's staged files staged, where they used to refuse.
- Pull and push are refused while a pull or a merge is stopped; a fetch also runs on a detached
  `HEAD`.
- A fetch stops after 2 minutes without an answer, a pull or a push after 10, so a hung remote never
  holds the write queue.
- A file over 1 MiB is listed without line counts, and its diff needs "Show the whole diff".
- A rename conflict is listed under its new path alone.
- Edits made outside `specs/` reach the page and the sidebar's count when the page or the tab is
  shown again, or with the next git write or fetch.
- Merge takes only a branch the page lists; removing a locked worktree is refused.
