## What and why

The human edits text in Neovim everywhere else, and asked for Vim's keys in all text fields of the
web UI, "as many keys as possible", client side and instant, without reinventing the wheel, and
would have dropped it if it cost too much. They also asked for a status indicator at the bottom
naming the mode, and an "open as buffer" shortcut that opens any file, like the inbox or the
priorities, as the text it is. The answers made every field one CodeMirror editor, Markdown
highlighted even without Vim; the spec's review added a Commit page that commits each branch apart,
with a message the human can rewrite, since a buffer's save never commits.

## Behaviour

- **Every text field is one editor**: comments, answers, notes, the proposal editor, the inbox's and
  the priorities' rows, one-line fields, the composer, and a picker's filter, all but the sign-in
  password. Markdown is highlighted as typed, its marks dimmed, in a terminal's look over the
  theme's monospace font and Catppuccin colours, light and dark. Lines wrap in every field, never
  scrolling sideways. A one-line field refuses line breaks (a pasted "first\nsecond" reads "first
  second"), grows with its text to 9 lines, then scrolls inside; a several-lines field keeps its
  height by kind, scrolling past it; the composer grows upward to 20 lines, 9 on the phone, then
  scrolls, and still takes pasted and dropped images. A search's magnifier icon is gone: its
  placeholder says "Search".
- **A field's keys**: Ctrl+Enter or Cmd+Enter saves or sends any field; in a one-line field it is
  the field's Enter, which saves a row or a line. Enter adds a line in a several-lines field and the
  composer. Escape leaves the field keeping its text, so the page's keys work again, in every field,
  comments and notes included, which ignored it before; a changed row asks "Discard your changes?";
  inside a dialog, Escape is the dialog's. Nothing runs while an input method composes. Escape then
  Tab always leaves a field.
- **Vim mode**, a switch in the settings' Keyboard section and `vim_mode` in the settings file's
  `[keyboard]` table, off by default, gives every field the keys of CodeMirror's Vim engine:
  motions, operators, text objects, registers, macros, marks, and ex commands. A field opens in
  insert mode; Escape goes to normal mode, and Escape in normal mode does the field's Escape, so a
  changed row asks before cancelling; Escape after a pending key, like `d`, only drops it.
  Shift+Escape leaves from any mode. Enter in normal mode saves a row, and moves down a line
  elsewhere; in a picker's filter, as in LazyVim's picker, `j` and `k` in normal mode move its
  highlighted row and Enter opens it. `:w` is the field's Ctrl+Enter, `:q` leaves the field keeping
  its text, and `:wq` does both; in a one-line field, `:wq` saves and leaves without asking to
  discard what it saved. Opening `:` in a changed row neither saves nor closes it; clicking away
  from the prompt saves the row as clicking away from its text does. Registers, macros, and marks
  are shared by every field of the tab. A yank to the unnamed register also reaches the system
  clipboard; a delete never does, and `p` pastes Vim's register. Turning the switch off keeps a
  field's unsaved text in place. The engine loads in its own chunk only with the switch on and a
  fine main pointer: never on a phone or a touch screen, and as soon as a mouse is attached. Keys
  the browser keeps never reach it: Ctrl+W closes the tab, the Leave guard asking first over unsaved
  text.
- **Vim commands**: `vim_commands` in the same table, a list of lines like `"imap jj <Esc>"`, edited
  as one line each under the switch, run in order each time the engine starts, over a cleared set of
  mappings. A line the engine refuses shows under the field as `Line 2: <the engine's message>`; a
  value of the wrong type is a problem of the file, "Vim mode is true or false." or "Vim commands
  are a list of lines, like ["imap jj <Esc>"]." Saving keeps the file's comments and order, and a
  hand-formatted list's lines.
- **The status line in LazyVim's shape**, for everyone, on semi-wide and wide screens: lualine's
  sections with drawn triangle separators. With Vim on, it opens with the mode in its colour and
  Lucide mark: NAV grey with a compass outside a field, NORMAL blue with a square, INSERT green with
  a pencil, VISUAL, V-LINE, and V-BLOCK mauve with a dashed square, REPLACE red, COMMAND peach while
  the `:` or `/` prompt is open. Then the branch a page names, the page's key hints, the counts, and
  at the right end the cursor's place, like "Top 3:9", while a field has the focus. With Vim off,
  the same sections without the mode. A mode change in a field is read out once, politely. The
  phone's bar is unchanged.
- **A buffer for any file**: on a page showing one file that exists, the priorities, the inbox, a
  proposal or note file, a feature's document, a decision, or the constitution, `Space b`, "Open as
  a buffer", opens `/buffer/<path>`: the whole file, frontmatter included, fills the center column
  under a bufferline, "specs › PRIORITIES.md" with an unsaved mark, the sidebar beside it, no right
  column, and the status line naming its branch. Pages with no single file, and a missing or empty
  list file, offer no `Space b`. Its text scrolls in its own scroller, so Vim's screen motions work.
  With Vim on, it opens in normal mode at the file's start, keeping its mode at each focus. `:w` or
  Ctrl+Enter saves it as typed, a line break or an indent alone included, never committing; `:q`, or
  `b` outside the text, goes back, home when it was the first page opened, the Leave guard asking
  over unsaved text; `:wq` saves, then goes back; Escape only leaves the text. On the phone, the
  bottom bar holds Back and Save. A file of a feature's or change's folder, at any depth, opens and
  saves on its branch; every other Markdown file under `specs/`, a merged feature's included, on the
  default branch. Any other path, or one that climbs out of `specs/`, is refused. A save over a file
  changed since it opened writes nothing, and a banner offers "Copy my text" and "Load the new
  version"; a feature's file is refused while its agent works, "An agent is working on this feature.
  Stop it first, or wait for it." Unsaved text kept from before is restored with its notice.
- **The Commit page commits each branch apart**: one pane per branch with changes, the default
  branch's first, then each feature's or change's whose checkout holds files a buffer edited. A pane
  lists what its commit holds, a buffer's file as one `- Edit <path>` line in place of the
  structured lines; a feature's pane lists only the files a buffer edited, never an agent's work.
  Its message is a field holding the suggestion (`chore: edit specs/PRIORITIES.md`, or
  `chore(<slug>): edit spec.md`, `, and N more` past one). A rewritten message is unsaved text, in
  the store as `commit:<branch>#message`: marked "Unsaved message", guarded on leaving, restored
  with its notice, kept through a refused commit, and "Use the suggested message" brings the
  suggestion back. Commit commits the pane's files alone, with a typed message trimmed of the blank
  lines around it and otherwise verbatim; an empty one is refused, "A commit needs a message." Only
  a suggested message may amend the latest `chore:` commit of the lists, and a typed commit on the
  default branch is never amended later. Discard restores everything the pane lists, a buffer's
  files included, after asking. A feature's pane is refused while its agent works. With several
  panes, `j` `k` select one, Enter and `d` commit or discard it, and Ctrl+Enter in a message commits
  its pane; with one pane the page looks as before. On the phone, two panes put Commit and Discard
  in each pane, and one keeps them in the bottom bar.
- **Saving never commits a buffer's edit**: the record of an edit ends once any commit, by any
  route, takes its file. The lists' own commits, the inbox's and the priorities' commit bar and a
  proposal or note file's commit, hold a file a buffer edited only when it is `INBOX.md`,
  `PRIORITIES.md`, or the file committed, and still the files the lists link; a buffer's other edits
  are never swept in as edits or link repairs, and wait for their pane. Actions that say they
  commit, like submitting answers or a verdict, still commit at once.

## Design

CodeMirror 6 draws every field, with `@codemirror/lang-markdown` and `@replit/codemirror-vim`, the
Vim engine Overleaf and JupyterLab ship. The field components keep their props and callers; the
editor owns the element, its keys, and Escape; the Vim layer only calls the field's own actions, so
Escape keeps one meaning per field. CodeMirror adds about 176 KB compressed to every page; the
engine's chunk, about 42 KB, loads only with Vim on. The core owns what a buffer can read and write,
where it is written, which files a buffer changed, and each branch's pane.

## Gotchas

- **The tests drop happy-dom's `selectionchange`**: happy-dom fires it at once, inside the code that
  moved the selection, and CodeMirror reads it as the human's, starting an update inside its own,
  each one firing the next. The tests set an editor's selection through its view instead
  ([`setup.ts`](/packages/web/src/__tests__/setup.ts)).
- **The Vim engine lets Escape through in normal mode**, and consumes it only in insert and visual
  modes: the field's Escape sits after the engine's keys, in
  [`keys.ts`](/packages/web/src/fields/editor/keys.ts), and catches it there. Escape after a pending
  key, and Shift+Escape, which the engine does not know, are handled before the engine, in
  [`vim.ts`](/packages/web/src/fields/editor/vim/vim.ts).
- **The engine's `:` prompt lives outside the editor's `contentDOM`**, in a panel under the text: a
  blur toward it is no leaving, and the prompt's own blur as Enter or Escape closes it is not
  either, since the engine gives the focus back to the text at once; only a focus still outside a
  microtask later is ([`leave.ts`](/packages/web/src/fields/editor/leave.ts)). `:q` and `:wq` run
  after the prompt closes, else its focus return undoes the leave
  ([`vim.ts`](/packages/web/src/fields/editor/vim/vim.ts)'s `afterPrompt`).
- **CodeMirror swallows a dropped file**, reading it as text and cancelling the drop: the page's
  drop target listens on the window in the capture phase and takes every dropped file first
  ([`useImageDrop.ts`](/packages/web/src/attach/useImageDrop.ts)).
- **Chromium never gives a page Ctrl+W, Ctrl+T, Ctrl+N, their Shift forms, or Ctrl+Tab**: insert
  mode's Ctrl-w closes the tab, and nothing in a page can change it; the Leave guard is the only
  protection.
- **The engine has no option to yank to the clipboard**: the layer wraps its register controller's
  `pushText`, for yanks to the unnamed register only
  ([`vim.ts`](/packages/web/src/fields/editor/vim/vim.ts)).
- **The engine reports a refused command through a notification, not an error**: the commands run in
  an editor of their own, never drawn, whose `openNotification` catches the message
  ([`vim.ts`](/packages/web/src/fields/editor/vim/vim.ts)'s `runCommands`).
- **The editor has no `textarea` or `input`**: a page key that focused a field by querying one left
  the focus on the page; they focus the field's `EditorHandle`, or its content element.
- **A field taken down blurs**, and React's development mode takes fields down and up as they mount:
  such a blur must not save or close a row ([`leave.ts`](/packages/web/src/fields/editor/leave.ts)'s
  `takeDown`).
- **The typed commit's mark is one file in the git folder every worktree shares**: only a commit on
  the default branch, the only one that amends, writes it
  ([`amend.rs`](/crates/core/src/actions/amend.rs)).
- **CodeMirror styles its own elements**, which StyleX cannot reach: the look is an
  `EditorView.theme` over the theme's CSS variables, kept in step with Astryx by hand
  ([`theme.ts`](/packages/web/src/fields/editor/theme.ts)). The bundled fonts have no Powerline
  glyphs, so the status line draws its separators
  ([`Sections.tsx`](/packages/web/src/shell/status/Sections.tsx)).
- **An input method's dead key in normal mode** may insert its character: the engine's known gap.

## Questions

### Round 01

#### Q1: Which Vim engine should the fields use?

**Answer:** A, CodeMirror 6 with `@replit/codemirror-vim`, with "We don't need to style it exactly
like Astryx's though. It can look more 'terminal-like'".

#### Q2: Which fields get Vim?

**Answer:** C, every field, one-line inputs included: "There's a lot of gain, vim mode is super
convenient" there too, and "make sure that single line inputs wrap: on mobile, a long single line
input like a priority is impossible to edit properly".

#### Q3: What does Escape do once Vim is in normal mode?

**Answer:** A, Escape in normal mode does what Escape does today, leaving the field or cancelling a
row, asking first when it changed, and Shift+Escape does it from any mode.

#### Q4: Where does the mode show?

**Answer:** A, at the start of the status line while Vim is on, NAV outside fields: "Should use the
full mode name though, with an icon".

#### Q5: Which files can the buffer open?

**Answer:** A, any Markdown file under `specs/`, frontmatter included, from a leader key on its
page, saved with the proposal editor's check that the file did not change underneath.

#### Q6: Where does a yank go?

**Answer:** A, every yank also goes to the system clipboard, and `p` pastes Vim's register.

#### Q7: Can you add your own mappings, like `jj` for Escape?

**Answer:** A, a list of Vim commands in the settings file, like `imap jj <Esc>`, run when Vim
starts.

#### Notes

- **No Markdown highlighting**: "Let's add it if it's only 85kcal. Should be there for all text edit
  fields, even without vim mode": every field highlights Markdown, which made every field the
  editor, Vim on or off.

## Decisions

- **New: [Text editing](../decisions/text-editing.md)**: every text field is one CodeMirror editor,
  Markdown highlighted and wrapped, with Vim's keys from CodeMirror's engine behind a switch, off by
  default.
- **Changed: [UI components](../decisions/ui-components.md)**: views use Astryx wherever one fits,
  except text fields, which follow Text editing.
- **Changed: [Git](../decisions/git.md)**: tools commit the human's edits only when the human asks,
  on the Commit page or by an action that says it commits; starting a feature or a change may commit
  on its own.

## Changes after approval

- A buffer's save records its path beside the checkout it wrote; the Commit page lists a recorded
  path as one `- Edit <path>` line, and a feature's pane lists only recorded paths.
- A feature's or change's file at any depth of its folder is written on its branch; a merged
  feature's files on the default branch.
- A pane's Discard restores the files a buffer edited too.
- A several-lines field keeps its height, scrolling past it; only one-line fields and the composer
  grow. A search's magnifier icon was left out.
- The composer is the editor's third variant, growing to its own maximum, its folding sliding over
  150 ms, none with reduced motion.
- The page's drop target hears every drop first, in the capture phase, since CodeMirror swallowed
  files dropped on a field.
- A one-line field's Ctrl+Enter and `:w` run its Enter; Vim's `:` prompt is no leaving of a row, but
  clicking away from it is.
- `:q` is a field action of its own: in a buffer it goes back, while Escape only leaves the text. A
  buffer keeps Vim's mode at focus, normal as it opens.
- `:wq` in a one-line field saves it and leaves it without its Escape, which asked to discard what
  was just saved.
- Only a suggested message amends; a typed message's commit is never amended by a later suggested
  one, and only the default branch's typed commit is marked so.
- A buffer's record ends when any commit takes its file, not when the pane's commit returns, so a
  refused commit keeps its pane and an agent's later edit is not the human's.
- A buffer scrolls in its own scroller, for Vim's screen motions, and `Space b` is offered only for
  a file that exists; `:q` and Back go home when the buffer was the first page opened.
- A rewritten commit message is unsaved text, guarded on leaving and restored with its notice.
- The lists' commits leave a buffer's other edits out, for their pane, but still hold the files the
  lists link.
- A typed commit message is one text, committed verbatim, with no blank line put after its first
  line.
- A buffer's edit of a final line break or an indent alone counts as unsaved text.
- The Vim engine loads as soon as a mouse is attached, without a reload.
- The benchmark times the keystroke as its own row, `keystroke`, and its Start from the New page's
  slug dialog; it gates the spec's two targets and reports its other rows.
- Asked on the pull request: the picker's filter is the editor too, with Vim mode, and in normal
  mode `j` `k` move its highlighted row and Enter opens it, as LazyVim's picker.

## Follow-ups

- **The Commit page's server read takes 132 ms**, past the Performance decision's 100 ms SHOULD for
  a click: it reads every branch's pane. Caching each worktree's pane until its record or files
  change would fix it. Two feature pages, at 122 and 173 ms, miss it too, from their own server
  reads.
- **A reload while a typed message's commit lands** restores the message over the next changes of
  its branch, until its Discard.
- **A file put back to `HEAD` by hand**, outside the page, then edited by an agent before any save
  or discard, still reads as the human's buffer edit; recording the saved text's hash would end it.
- **The editor's look is kept in step with Astryx by hand**: an Astryx gap, with no themed code
  editor in Astryx.
