## What and why

An inbox triage could only be answered and applied. A stale triage, or one asked for too early,
blocked "Organize with AI" until someone deleted `specs/INBOX-TRIAGE.md` by hand. The human can now
dismiss a triage, answered or not, and ask for a new one.

## Behaviour

- The triage's banner on the inbox page has Dismiss, a ghost button after its own action, "Answer
  it" or "Apply the answers", at every width. Dismiss deletes `specs/INBOX-TRIAGE.md` and commits
  the deletion alone, `chore: dismiss the inbox triage`, through the write queue. The banner goes,
  and "Organize with AI" comes back. The inbox and every other file stay as they are, uncommitted
  notes included. Like other commits, a dismissal has no undo.
- A triage committed as it is goes at once, since git keeps it. A triage with changes not committed,
  such as answers saved but not submitted, asks "Dismiss the inbox triage?" first, with Keep it or
  Dismiss.
- The core refuses three cases and writes nothing:
  - a triage changed since Dismiss read it;
  - a triage already gone, with "No inbox triage waits.";
  - a triage never committed, with "INBOX-TRIAGE.md was never committed: delete it by hand to
    dismiss it.", since git would keep no copy.

  The inbox page shows each refusal under its title.

- The decisions check has no Dismiss, and the core refuses to dismiss it.
- By hand, the skill's inbox reference says to delete the file and commit its deletion alone, after
  asking the human when the triage holds answers not committed. Its refusal of a second triage now
  says "answer or dismiss".

## Design

The core's `dismiss` in [`actions/default_round.rs`](/crates/core/src/actions/default_round.rs) owns
the rule:

- it refuses a missing triage, one never committed, and one changed since read;
- it then deletes the file and commits it with `commit_only`, as Submit does.

`DefaultRound::dismissed_subject` names the commit, and is `None` for the decisions check, which
refuses it. Around it:

- `api::dismiss_round` takes the write lock and reaches the default branch's checkout.
- The binding's `dismissTriage` exposes it.
- The server's `defaultRound.dismiss` in
  [`inbox-mutations.ts`](/packages/server/src/fate/inbox-mutations.ts) runs it through `listCommit`
  and answers with the inbox.

In the web UI:

- `DismissTriage` in [`InboxTriage.tsx`](/packages/web/src/InboxTriage.tsx) reads the round when
  pressed, for its hash and whether it differs from the tip, and asks first when it does.
- `RoundBanner` in [`StartChat.tsx`](/packages/web/src/StartChat.tsx) takes it as a second action.

Tests:

## Gotchas

- Dismiss uses `onClick`, not Astryx's `clickAction`. `clickAction` runs as a React transition,
  which holds back the confirmation's state updates until the action ends, and the action waits for
  the answer, so the question never shows.
- Dismiss reads the round when pressed, not while the banner draws. `useRound` suspends, and the
  nearest boundary is the page's, so a triage appearing live would swap the whole inbox for its
  loading state.
