# Record: Tab completion for `ura` in fish and zsh

> [!NOTE]
>
> The record of a merged change, not instructions to follow. Started on 2026-10-20, finished on
> 2026-10-20, in [its pull request](https://github.com/mrtolkien/uraeda/pull/51). Its full files are
> in git: `git log -- specs/changes/2026-10-20-shell-completions/`.

## What and why

The proposal asked for Tab to complete `ura`'s commands in fish and zsh, a line of **Next** in the
priorities. In the chat that started it, the human chose dynamic completion, where the shell asks
the `ura` binary at each Tab, so completion never goes stale after an upgrade.

## Behaviour

- `ura` answers `COMPLETE=<shell>` before parsing its arguments: alone, it prints the shell's
  registration script; with the words of a command line, the candidates for the word being
  completed. Every command behaves as before without the variable.
- Tab completes subcommands, flags, and their values: drafts and postponed folders after `start`;
  the features and changes under way, by slug, after `next`, `review`, `check`, and `note --about`;
  the merged ones with a worktree or a branch left after `clean`; the inbox's categories after
  `note --category`; files and folders after `check` and `add`.
- After `answer`, Tab completes the rounds waiting for answers, by slug, then the open questions and
  `notes` of the round `ura answer` would pick. Once a target is typed, its round's open questions
  alone; once a question is typed, nothing. An answered round offers nothing.
- Completion reads local branches and files only, never `gh`: about 200 ms for a value in a
  repository with a dozen branches, a few milliseconds for a subcommand.
- zsh's script completes on a session's first Tab, sourced from `~/.zshrc` or autoloaded as `_ura`
  from `fpath`, as packages install it.
- `ura install --completions` sets completion up in `$SHELL`: in fish, it writes
  `COMPLETE=fish ura | source` to `ura.fish` in fish's completions folder (`$XDG_CONFIG_HOME/fish`
  or `~/.config/fish`); in zsh, it names the line to add to `~/.zshrc` and writes nothing. It never
  overwrites a file it did not write, even one that is not UTF-8. Alone, the flag leaves the skill
  as it is. A terminal install offers it: a question in fish when the file is missing, the zsh line
  in zsh.
- The Nix package installs both scripts, in `share/fish/vendor_completions.d/` and
  `share/zsh/site-functions/`. The Homebrew formula installs them through Homebrew's
  `generate_completions_from_executable` with `shell_parameter_format: :clap`.

## Design

[`clap_complete`](https://docs.rs/clap_complete/4.6.11/clap_complete/env/index.html)'s dynamic mode,
`CompleteEnv`, runs first in [`main`](/crates/cli/src/main.rs). It is pinned to an exact version,
`=4.6.11`, since that mode is exempt from semver. It grew the release binary from 7,202,200 to
7,284,952 bytes (+1.1%).

- [`complete.rs`](/crates/cli/src/complete.rs): the candidates of each argument, attached with
  `#[arg(add = ...)]`, read from the workspace without its pull requests. clap gives a value
  completer the word being completed alone, so `answer`'s reads the words typed before it from the
  request, `ura -- <words>`, with zsh's and bash's `_CLAP_COMPLETE_INDEX`. It also wraps clap's zsh
  script with a tail, as cobra's scripts have, that completes when zsh autoloads the file: clap's
  alone only registered itself on that first Tab.
- [`target::waits_for`](/crates/core/src/target.rs): whether a feature waits for answers or a
  review, shared by the commands' default target and the completion.
- [`shell.rs`](/crates/cli/src/shell.rs) and [`install.rs`](/crates/cli/src/install.rs): the
  `--completions` flag and the terminal's offer.
- [`flake.nix`](/flake.nix): `installShellCompletion` from the built binary, skipped by a cross
  build, which cannot run it.
- [`publish-homebrew.yml`](/.github/workflows/publish-homebrew.yml): dist's formula installs only
  the binary, with no setting for more
  ([axodotdev/cargo-dist#2429](https://github.com/axodotdev/cargo-dist/issues/2429)). This job,
  called from `publish-jobs` in [`dist-workspace.toml`](/dist-workspace.toml) in place of dist's
  own, adds the completion line after `install_binary_aliases!` before pushing the formula to the
  tap, and fails before pushing when that line is gone.
  [`release.yml`](/.github/workflows/release.yml) is regenerated by dist 0.33.0.

## Questions

### Round 01

#### Q1: How should completion reach your shell?

**Answer:** A and B: the Nix package installs the scripts and the README gives the lines, and
`ura install` sets it up too, keeping it a change: "Writing to `~/.config/fish/completions/ura.fish`
is ok (no conflict, it's its own file), but for ~/.zshrc let's just tell the user to do it".

## Changes after approval

- `clean` completes the merged features it can clean, where the round said the started ones, which
  it refuses.
- The README says which zsh finds the packages' scripts without setup: one from the same package
  manager; macOS's own zsh needs their folder on `fpath`, or the `~/.zshrc` line.
