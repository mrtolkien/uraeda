# Record: "Master" PR

> [!NOTE]
>
> The record of a merged feature, not instructions to follow. Started on 2026-11-03, finished on
> 2026-11-04, in [its pull request](https://github.com/mrtolkien/uraeda/pull/89). Its full files are
> in git: `git log -- specs/2026-11-03-master-pr/`.

## What and why

Features built in parallel conflicted when they merged, half the time only in workflow files every
branch edited: `PRIORITIES.md`, where each finish removed its own line next to another start's,
`INBOX.md`, where agents' notes went at the end of the same categories, and old records whose links
both sides repaired. The proposal asked for pull requests that merge smoothly, perhaps through a
"master" pull request; once the options were laid out, the human kept only the file changes:
branches stop writing the shared files, and no pull request flow changes.

## Behaviour

- **A branch never writes `PRIORITIES.md` or `INBOX.md`.** The finishing commit writes the record
  and deletes the folder only. A merged feature's or change's line stays in Now; the priorities, in
  the web UI's list, its pane, and the Home, show it with done's icon, "Merged", and `#N` for its
  pull request (the open one, else the record's), open `/f/<folder>`, and offer no edit in place,
  Start, Expand, move, or nesting. Only a line linking the folder, or its `proposal.md`, reads as
  merged: a link to its record is an ordinary line. `ura check` and `--fix` leave the line's link
  into the deleted folder alone.
- **`ura clean` removes the merged line** with the worktree and the branch, on the default branch,
  with its nested lines, in `chore(<slug>): remove "<name>" from the priorities`, committing
  `PRIORITIES.md` alone. With other uncommitted changes there it removes the line without committing
  and says `PRIORITIES.md had uncommitted changes: the line is removed but not committed.`; when a
  hook refuses, `a hook refused the commit: the line is removed but not committed.` A dry run writes
  nothing. A merged feature with only its line left is something to clean, and `ura status` and
  `ura next` name it: `merged: line in the priorities left, run ura clean`.
- **An agent's note is a note file of its own.** `ura note <text> --agent` in any branch's checkout
  but the default one writes `specs/notes/<slug>-<four words>.md`, apostrophes dropped, `-2`, `-3`
  when taken, the words alone without a slug, with the frontmatter `agent: true`, `about`, and
  `category`, quoted when YAML would misread them, and the note as `# ` title; it commits the file
  alone with `chore: add "<note>" to the inbox`. On the default branch it refuses:
  `--agent writes in a feature's or a change's worktree, never on the default branch`.
- **The inbox shows every note file no link of `INBOX.md` points to**, nested links included, at the
  end of its category as `ura note` would add its line: a category `INBOX.md` lacks after its own,
  none after the notes without a category. Its id is its path. The web UI, `ura inbox`, its `--json`
  (category, plain text, marks, file, with `version`), category completion, the triage, and the live
  updates read through the same reader. A line linking the file wins over its fields.
- **An action on an agent's note writes its line first**, at the end of its category, then runs as
  for a linked note file; a refused action leaves every file as it was. A move puts the line where
  the note goes, drops the file's `category`, and counts drop positions as the inbox shows them; one
  that lands where the note showed writes nothing. A drop under an agent's note nests under its
  line. A category's rename or removal writes its agents' notes' lines first. Making it a proposal
  moves the file without its frontmatter. Removing it deletes the file, in
  `chore: remove "<note>" from the inbox`, only when the file is as committed; otherwise it refuses:
  `<path> has uncommitted changes: the note was not removed`. Undo of a removal restores the file
  alone. The commit bar diffs `INBOX.md` joined with the agents' notes, so their removals and moves
  are changes, and Discard restores a dropped `category`.
- **The catch-up settles the shared files by rule**: a conflicted record of `specs/done/` takes the
  default branch's side, and `ura check --fix` repairs the branch's links again, unless the branch's
  side holds more than links, which stops the agent; a generated file is regenerated by the build;
  an old branch's edit of `PRIORITIES.md` or `INBOX.md` takes the default branch's side. A postponed
  feature's line moves on the default branch, in the commit after its merge.

## Design

Branches add files and never edit the human's shared files, as changelog tools ended the same
conflicts with one file per entry.

- [`files/inbox/agent.rs`](/crates/core/src/files/inbox/agent.rs) owns what an agent's note is: the
  note files no link of `INBOX.md` points to, their fields, their line, and `joined`, `INBOX.md`
  with those lines added where `inbox::add` puts them.
  [`files/inbox/read.rs`](/crates/core/src/files/inbox/read.rs) `read(text, files)` places them in
  the `Inbox` every reader returns.
- [`actions/inbox/agent.rs`](/crates/core/src/actions/inbox/agent.rs) is the one wrapper every
  action by id goes through: it writes the line, runs the action, and takes the line back on
  refusal; it also owns the removal, the Undo, the moves' positions, and the category edits.
  [`actions/changes/texts.rs`](/crates/core/src/actions/changes/texts.rs) gives the commit bar the
  joined texts at `HEAD` and now.
- [`actions/inbox/agent_file.rs`](/crates/core/src/actions/inbox/agent_file.rs) writes the file for
  [`cli/src/note.rs`](/crates/cli/src/note.rs); [`cli/src/inbox.rs`](/crates/cli/src/inbox.rs)
  prints the inbox.
- [`actions/clean.rs`](/crates/core/src/actions/clean.rs) removes the line through
  `actions::priorities::remove_linked`, shared with the drop;
  [`workspace/links.rs`](/crates/core/src/workspace/links.rs) `links_folder` is the one rule of a
  merged line, read by `Linked::merged`, the clean, and the priorities' removal.
- The web's [`PrioritiesList.tsx`](/packages/web/src/lists/PrioritiesList.tsx) and
  [`ProposalPane.tsx`](/packages/web/src/pane/ProposalPane.tsx) draw `ProposalItem.merged`.
- The skill's finish, catch-up, change, inbox, projects, conventions, and CLI references, the
  `specs/README.md` template, the example's note file, and `docs/` say the same rules.

## Replaced behaviour

- **The finishing commit removes the feature's line from `PRIORITIES.md`.** In the skill only; no
  test guarded it.
- **An agent's note is a line of `INBOX.md` on its branch.** Guarded by
  `an_agents_note_from_a_feature_worktree_stays_on_its_branch`, removed, and
  `an_agents_note_about_a_feature` and `an_about_naming_a_change_writes_its_slug`, rewritten, in
  `crates/cli/tests/note.rs`.
- **A note file no note of `INBOX.md` links is a warning, `layout.unlinked-note`.** Guarded by
  `an_unlinked_note_file_is_a_warning`, removed from `crates/core/tests/check.rs`; the check's file
  `check/notes.rs` is gone.
- **The catch-up takes the default branch's `PRIORITIES.md`, with the feature's line kept.** In the
  skill only.
- **`ura note --agent` on the default branch writes a line.** Now refused, as the git decision asks.

## Gotchas

- An agent's note's id is its path, not `note-<n>`: a merge bringing another note file would shift
  counted ids, and the inbox's hash covers `INBOX.md` alone, so a stale counted id would not be
  refused ([`files/inbox/read.rs`](/crates/core/src/files/inbox/read.rs)).
- The inbox's parser finds no note in a text without its title line, so an agent's note's line is
  read under `# Inbox` ([`files/inbox/read.rs`](/crates/core/src/files/inbox/read.rs)).

## Decisions

- [Git](../decisions/git.md): a feature's or a change's branch never writes `PRIORITIES.md` or
  `INBOX.md`, and an agent's inbox note is a note file of its own, never written on the default
  branch.

## Changes after approval

- `ura note --agent` on the default branch is refused, where the plan had kept writing a line: the
  git decision forbids an agent's note there.
- Removing an agent's note refuses a file that is not as committed, as the spec's edge case keeps a
  linked note's edited file, rather than deleting it whatever it holds.
- The removal's subject shortens the note at 40 characters, as every inbox subject does, rather than
  after its first words as the spec's example read.
- `ura clean`'s messages listing what is left name the line:
  `Nothing to clean: no merged feature has a worktree, a branch, or a line of the priorities left.`
- An agent's note made a proposal leaves its frontmatter behind, and its Undo writes the file back
  as committed.
- A category's rename or removal, a drop under an agent's note, and positions among agents' notes
  act on the agents' notes too, which the spec did not name.

## Follow-ups

- An agent's note under Deferred fixes: Undo of a category's removal leaves its agents' notes' lines
  in `INBOX.md` when `INBOX.md` had other uncommitted edits; the inbox shows the same notes.
- Two branches noting the same first four words about the same third feature, with `--about`, add
  the same file name and conflict.
