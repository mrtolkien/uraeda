# Plan: Add a bugfixing/low impact change flow

**Goal:** Replace the unused bug flow with changes: a light flow from a typed request or a draft to
a pull request, with its own step table, folder, branch, web UI page, and skill reference.

**Architecture:** The core owns the item's kind (`Feature` or `Change`), from its branch prefix
`change/`, its folder `specs/changes/`, and its record's `kind`. It also owns the change's step
table, the files a change's folder may hold, starting a change from a draft or a typed text, the
proposed slug, and a finished item's pull request URL. The server only builds the agent's messages
and starts a change's first run. The web UI only draws what the core says. The skill's new
`references/change.md` owns the agent's rules. See the [spec's architecture](spec.md#architecture).

**Spec:** [spec.md](spec.md): the plan argues from the spec, so the implementer reads both.

## Review focus

1. **A dated `specs/changes/<folder>` without its `change/` branch, or a `change/` branch without
   its folder.** It is not an item, like a feature folder without its branch today, and no page or
   `ura status` row shows it. Task 2.
2. **The same slug started as a feature and as a change on the same day.** The second start is
   refused: `specs/<folder>`, `specs/changes/<folder>`, a branch `<folder>` or `change/<folder>`,
   and a record `specs/done/<folder>.md` each take the name. Task 5.
3. **A typed request whose first line is blank, or only spaces.** The title is the first non-blank
   line, and the text keeps its blank lines after it. Task 5.
4. **A change's proposal committed from the web UI's editor.** `text.rs` accepts
   `specs/changes/<folder>/proposal.md` as a proposal, so editing it commits
   `chore(<slug>): edit the proposal` on the change's branch. Task 2.
5. **A change whose agent is already running when "Start the change" sends its first run.** That
   cannot happen for a new folder. The mutation still goes through `Sessions.send`, which queues a
   run behind a running turn, so no second process starts. Task 7.
6. **Leaving "New change" with text typed.** The text comes back on the next visit, from the unsaved
   store, and Start clears it. Task 9.
